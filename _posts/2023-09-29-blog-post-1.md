This guide explains how to set up remote access from your home laptop to a campus intranet server using a cloud relay (e.g., AWS EC2). The technique uses **reverse SSH tunneling** so the campus machine initiates the outbound connection, bypassing firewall restrictions.

<div class="key-takeaways">
<h3>Overview</h3>
<ul>
<li><strong>Problem:</strong> Campus servers sit behind a firewall — you can't SSH in directly from home.</li>
<li><strong>Solution:</strong> The campus machine opens a reverse tunnel to a cloud server; you connect through the cloud server.</li>
<li><strong>Tools:</strong> <code>ssh</code>, <code>autossh</code>, <code>systemd</code> for auto-reconnection on boot.</li>
</ul>
</div>

## Architecture

<div class="network-diagram">
  <span class="node">C<span class="node-label">Home Laptop</span></span>
  <span class="arrow">——SSH——&gt;</span>
  <span class="node">B<span class="node-label">Cloud Server</span></span>
  <span class="arrow">&lt;——Reverse SSH——</span>
  <span class="node">A<span class="node-label">Campus Server</span></span>
</div>

| Machine | Description | Network |
|---|---|---|
| **A** | Campus server (behind firewall) | Campus intranet |
| **B** | Cloud relay (e.g., AWS EC2) | Public IP |
| **C** | Your home laptop | Any network |


## Part 1 — Set Up A → B (Campus to Cloud)

<div class="step-card">
<h4>Step 1 — Generate SSH key pair on A</h4>
<p>Create a passwordless key pair so <code>autossh</code> can reconnect without human intervention.</p>
<pre><code class="language-bash">ssh-keygen -t rsa
# Press Enter for all prompts
# Key will be saved to ~/.ssh/id_rsa
</code></pre>
</div>

<div class="step-card">
<h4>Step 2 — Copy public key to B</h4>
<pre><code class="language-bash">ssh-copy-id -i ~/.ssh/id_rsa.pub ubuntu@CLOUD_IP -p 22
</code></pre>
</div>

<div class="step-card">
<h4>Step 3 — Install autossh on A</h4>
<p><code>autossh</code> monitors the SSH connection and automatically restarts it if it drops.</p>
<pre><code class="language-bash">apt-get install autossh
</code></pre>
</div>

<div class="step-card">
<h4>Step 4 — Test the reverse tunnel</h4>
<pre><code class="language-bash">autossh -M 9991 -NfR 8990:localhost:22 ubuntu@CLOUD_IP
</code></pre>
<p>Verify on <strong>B</strong> by running:</p>
<pre><code class="language-bash">watch -n 1 netstat -tnlp
</code></pre>
<p>You should see port <code>8990</code> listening.</p>
</div>

<div class="callout callout-info">
<strong>What does <code>-NfR 8990:localhost:22</code> mean?</strong>
It tells SSH to forward port <code>8990</code> on B back to port <code>22</code> (SSH) on A — a reverse tunnel. <code>-N</code> means no remote command, <code>-f</code> runs in background.
</div>

## Part 2 — Automate with systemd

To ensure the tunnel survives reboots and network interruptions, create a systemd service on **A**.

<div class="step-card">
<h4>Step 5 — Create the service file</h4>
<pre><code class="language-bash">vim /lib/systemd/system/autossh.service
</code></pre>
<p>Paste the following:</p>
<pre><code class="language-ini">[Unit]
Description=Auto SSH Tunnel
After=network-online.target

[Service]
User=YOUR_USER_NAME
Type=forking
ExecStart=/usr/bin/autossh -NR 9888:localhost:22 -i /home/YOUR_USER_NAME/.ssh/id_rsa ubuntu@CLOUD_IP -p 22
ExecReload=/bin/kill -HUP $MAINPID
ExecStop=/bin/kill -TERM $MAINPID
KillMode=process
Restart=always

[Install]
WantedBy=multi-user.target
WantedBy=graphical.target
</code></pre>
</div>

<div class="step-card">
<h4>Step 6 — Enable and start the service</h4>
<pre><code class="language-bash">systemctl enable autossh
systemctl start autossh
systemctl status autossh
</code></pre>
</div>

<div class="callout callout-tip">
<strong>Tip</strong>
If the service fails to start, check that the SSH key path and username in the service file are correct. Use <code>journalctl -u autossh</code> to inspect logs.
</div>

## Part 3 — Connect C → A (Home to Campus)

From your home laptop **C**, connect in two hops:

<div class="step-card">
<h4>Step 7 — SSH into the cloud server B</h4>
<pre><code class="language-bash">ssh ubuntu@CLOUD_IP
</code></pre>
</div>

<div class="step-card">
<h4>Step 8 — Hop through to campus server A</h4>
<p>From B, connect through the reverse tunnel:</p>
<pre><code class="language-bash">ssh -p 9888 YOUR_USER_NAME@127.0.0.1
</code></pre>
</div>

<div class="callout callout-warning">
<strong>Security note</strong>
Keep your cloud server's SSH access locked down — use key-only authentication, disable password login, and restrict the security group to your IP range if possible.
</div>

You now have remote access from your home laptop to your campus intranet server, with automatic reconnection on boot.
